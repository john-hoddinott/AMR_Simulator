# Waste And Volume-Based Generation

## Aim

This page explains how waste and volume-based generation can create tasks from
accumulated demand rather than from a fixed list of manual tasks.

Waste generation is useful for modelling collections that depend on how much
material has accumulated in a department, waste stream, or container.

## When To Use This

Use waste or volume-based generation when a workflow is triggered by demand
building up over time.

Examples include:

- waste containers reaching a collection threshold
- department waste accumulating during operating hours
- shared waste bins serving several departments
- tracked items falling below a top-up threshold
- scheduled checks that only create work when a threshold has been reached

For a simple demonstration, manual tasks or scheduled generated tasks are easier
to understand.

## Key Concepts

**Waste stream**

A named waste category with assumptions such as payload type, container capacity,
and full threshold.

**Container capacity**

The volume a waste container can hold, usually expressed in cubic metres.

**Full threshold**

The fraction of capacity at which a container is treated as ready for
collection. For example, a 0.8 threshold means collection is triggered at 80%
of capacity.

**Department waste**

Waste generated by a department based on demand fields such as bed count,
patient turnover, staff count, and waste coefficients.

**Shared container**

A container or bin group that can accumulate waste from more than one
department or source.

**Seeded container**

A physical container assumed to exist at the start of the simulation. This is
important when modelling whether a generated task collects an existing bin or
creates an abstract collection movement.

## Two Related Waste Mechanisms

The code contains two related ways to generate waste-related tasks.

One is the category-based task generator. It can use generation modes such as
threshold, hybrid, scheduled threshold, and continuous accumulation. It can also
use waste stream settings from departments.

The other is a department waste generator. This calculates waste accumulation
from department fields and creates collection tasks when stream thresholds are
reached.

From a user perspective, both can create waste collection work. The important
thing is to know which mechanism is active in the scenario.

## Waste Streams

A waste stream defines the operational assumptions for a type of waste.

Useful fields include:

- waste stream name
- payload type
- container capacity
- full threshold fraction

The payload must be compatible with at least one resource permitted by the
waste flow's delivery policy. If no eligible AMR or porter can carry it,
generated waste tasks may remain pending or fail even if generation is correct.

## Department Waste Settings

Departments can have waste stream settings. These connect a department to the
waste streams it can generate.

Department waste calculations can use:

- bed count
- patient turnover
- staff count
- operating hours
- active days
- waste coefficients

The code includes a rate calculation using bed count, turnover per hour, and
staff count. This means those values can materially affect simulated waste
demand.

## Threshold-Based Collections

Threshold generation creates a task when accumulated volume reaches a configured
threshold.

The threshold may be set directly, or derived from:

- container capacity
- full threshold fraction

For example, a 1.0 m3 container with a 0.8 full threshold would trigger at
0.8 m3.

## Scheduled Threshold Collections

Scheduled threshold generation combines a scheduled check with a threshold.

This is useful when a collection round happens at planned times, but only
collects when enough material has accumulated.

If the threshold is not reached, the scheduled time may not create a task.

## Physical Containers

Some waste logic tracks whether a physical container exists and whether it is
empty or full.

This matters when:

- containers are present at the start of the simulation
- a task should collect an existing container
- an emptied container should be returned
- shared container groups are used

Physical-container modelling is more realistic, but also harder to reason about.
Use it only when the operational question needs that detail.

## Step 1: Decide The Waste Modelling Level

Choose whether the scenario needs:

- simple manual waste tasks
- scheduled generated waste tasks
- threshold-based volume accumulation
- department-driven waste generation
- physical container behaviour

Start with the simplest model that answers the question.

## Step 2: Define Waste Streams

For each waste stream, check:

- the stream has a clear name
- the payload exists
- the payload can be carried by a resource permitted by the flow
- staff roster windows are long enough for porter-only collections
- AMR or staff type restrictions match the intended waste resource
- container capacity is greater than zero
- full threshold is between zero and one

## Step 3: Link Departments

For department-driven waste, assign waste streams to the departments that should
generate that waste.

Check that each department has:

- active days
- operating hours
- relevant demand fields
- pickup and dropoff assumptions
- a valid route from collection point to disposal point

## Step 4: Run A Small Test

Before running a whole-hospital scenario, test one waste stream or one group of
departments.

Review:

- number of generated tasks
- release times
- pickup and dropoff locations
- threshold volumes
- failed tasks
- return or container behaviour

## Common Problems

**Waste tasks are not generated**

The department may be inactive, the stream may not be assigned, the threshold
may not be reached, or waste generation may be disabled.

**Too many waste tasks are generated**

Check container capacity, threshold fraction, department demand fields, and
whether more than one waste generation mechanism is active.

**Waste tasks fail**

Check delivery-resource mode, payload compatibility, staff roster windows,
location names, route graph connections, route profiles and lift access.

**Collections appear at unexpected times**

Check scheduled times, department operating hours, active days, and whether the
mode is threshold-based or scheduled-threshold.

## Modelling Notes

Waste and volume-based generation can produce realistic demand patterns, but it
is sensitive to assumptions. Small changes in capacity, threshold, or department
demand can change the number and timing of tasks.

For operational comparison, record the waste-generation mode, active streams,
container assumptions, and department demand values used in each scenario.
